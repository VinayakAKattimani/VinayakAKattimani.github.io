AI engineering

How I build AI applications.

A language model is only one part of an AI product. Most of the engineering is in what surrounds it.

01Frame the problem

Before picking a model I decide what a good answer looks like: who is asking, what they need, and what the system must never get wrong. That shapes every later choice.

02Prompt and context design

Prompts set role, tone and boundaries. Conversation history is carried forward and trimmed so follow-up questions stay coherent, and I iterate on prompts against real example questions to keep answers consistent.

03Retrieval-augmented generation (RAG)

Models do not know your documents. I ingest files, split them into chunks, embed them and store them in a vector database (Qdrant). At question time the closest chunks are retrieved and passed to the model as context, which grounds answers in source material and reduces invented detail.

04Model and provider integration

LLM calls live in their own service behind an adapter layer, so Groq, OpenAI or a local Ollama model can be swapped through configuration without touching the rest of the application. Responses are streamed so users see output quickly.

05Voice and telephony

Speech-to-text (Whisper, ElevenLabs) turns audio into text, the same conversation pipeline produces the answer, and text-to-speech (Kokoro, ElevenLabs) speaks it back. Calls come in over a real phone line through Twilio.

06APIs, validation and packaging

FastAPI services with Pydantic validation, JWT authentication and Swagger documentation, endpoints tested in Postman, and every service containerised with Docker Compose.

07Designing for failure

Irrelevant retrieval, provider timeouts, noisy audio and context overflow are normal. Each needs a fallback path rather than just a happy path.

The problem

Useful assistants need relevant answers, preserved context and consistent behaviour — plus speech, retrieval and provider integrations beyond plain text generation.

The approach

Separate services for gateway, auth, conversation, knowledge, LLM and audio, so each responsibility is isolated and the LLM provider can change independently.

Engineering considerations

Context handling in the conversation service, retrieval over a vector store, streamed LLM responses, JWT auth, Pydantic validation, env-based configuration, Docker Compose.

What it demonstrates

Integrating AI components into an application, rather than using an LLM as a standalone chat box. No performance or accuracy results are claimed.
